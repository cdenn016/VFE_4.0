# VFE 4.0 multi-agent simulation

This suite implements the finite normalized Gaussian realization of the live MultiAgentELBO theory. One engine runs a single context with an agent lattice, local sections over a periodic flat 2D base, or local sections over a periodic flat 3D base. The starting gauge backend is GL(K,R). The design and revised implementation plan are in `docs/superpowers/`.

Open `run_simulation.py` in your editor, select `C:/anaconda/python.exe`, edit its complete literal `CONFIG` dictionary, and press Run. All 67 supported keys are visible there. Its current values select the validated 512-agent point lattice, K=4, CUDA, and 100 sweeps. There are no command-line arguments. The installed interpreter has CUDA Torch; bare Python on this machine has CPU-only Torch. Set `CONFIG['output']['viewer']=True` for pause, resume, one-sweep, and stop controls. Headless execution uses the same inference engine. A stopped run saves its state and reports `stopped`.

The section inspector selects an agent, its belief or model channel, a fiber component, and mean or standard deviation. Enter numeric choices and press Enter; their ranges appear below the inputs. Spatial images show the evaluated local section in that agent's frame, with gray outside its support. The 3D z slider selects periodic, endpoint-exclusive planes and recenters at the selected agent's center when the agent changes. Paused controls redraw the captured coefficient law without advancing inference; One sweep refreshes the display even before the configured snapshot interval. The preview uses twice the base grid resolution in each displayed direction. Point mode shows the selected law at c*. The active dictionary still has `viewer=False`.

The live dashboard adds the full population map and three reference-frame panels: truth fixture, population nodal mean, and signed mean-minus-truth error. Click a center to select its agent, or enter an agent ID. The map highlights the selected patch's design nodes, active agents at the selected context, and incoming source probabilities for the chosen channel/context row; self probability is labeled separately. The Context ID input chooses a finite design context. In 3D, an explicit context moves the slice to its z plane; moving the slice chooses the nearest nodal context at the selected agent's xy location. Click selection uses the current z to distinguish overlapping projected centers. Routing always uses the labeled finite context, including at intermediate display slices. A missing receiver, disabled channel or empty row is reported explicitly. Spatial arrows follow shortest periodic displacements and repeat at boundaries.

To inspect an existing run, open `run_viewer.py`, edit its literal `CONFIG`, and press Run with `C:/anaconda/python.exe`. Set `checkpoint` to a `.pt` checkpoint file or a run directory; a directory selects its `final_state.pt`. Relative paths resolve beside the launcher, independently of the editor's working directory. The default path is a placeholder that you must replace. Use forward slashes or a raw Python string for Windows paths. `device='cpu'` maps saved tensors to CPU even if the run used CUDA; `device='cuda'` explicitly selects CUDA display. `cpu_threads` accepts integers from 1 through 4 and caps Torch/OpenMP/MKL/OpenBLAS work for this process. The launcher uses the installed Qt backend and has no command-line arguments.

The saved-run inspector restores the checkpoint's recorded VFE history and opens the same six panels without performing inference or evaluating VFE. Pause/resume and One sweep are disabled; Close ends the window. The other selectors work normally. The dashboard shows the stored checkpoint state, while history contains only its recorded sweeps; missing history is labeled unavailable. It does not reconstruct intermediate states from scalar history. The inspector maps only the loaded copy's display-device metadata and does not restore RNG streams, change Torch's deterministic setting, write checkpoints or create a continuation run. Continue inference separately through `resume_simulation` when that is intended. Existing simulation CONFIG dictionaries are untouched.

The reference panels average nodal coefficient means over agents covering each design point. They use the chosen channel/component and retain uncovered-point masks. Odd 3D preview slices show labeled periodic linear interpolants of adjacent stored planes, requiring coverage on both planes. These population averages describe the current recognition means; they are not a posterior for a separate collective field. The Mean/Std. deviation selector applies to the local section panel; the reference panels continue to compare means. Gray images indicate uncovered values, while gray centers indicate agents absent at the selected context. Point mode retains the agent-lattice map and per-agent reference curves. All selectors inspect the captured coefficients and beta without advancing inference.

The presets are `tiny_point`, `tiny_spatial_2d`, `tiny_spatial_3d`, `point_lattice_512`, `spatial_2d_512`, `spatial_3d_512`, and `spatial_2d_1024_sparse`. The tiny presets use CPU for formula and continuation checks; the spatial ones place 2^d agents with overlapping 3^d patches on a 4^d grid, so they exercise spatial records, cross-node covariance and inter-agent copies. Change `population.n_agents` together with its lattice or center-grid dimensions; the loader rejects inconsistent shapes. Full patch Gaussian covariance is the default. `node_blocks` is an explicitly different recognition family; it retains full K by K covariance within each node. The Fisher-natural matter method currently requires `full_patch`. Coverage can be required or explicitly allowed to be incomplete.

The flat connection is induced by the fixed smooth agent frame: `Omega(y,x)=U(y)U(x)^-1`. Inter-agent attending directions each have an independent primitive generator. A formal inverse is not a second likelihood copy. Held links give a normalized fixed Gaussian/source-label model with an exact VFE evaluation. Latent Gaussian links use antithetic samples, analytical matter expectations conditional on those samples, and Gaussian Fisher/BLR updates with the projected true Hessian. Acceptance uses common samples. Independent diagnostic samples report a separate estimate and standard error. Two samples form only one antithetic pair, so an error bar is unavailable. A nonzero loop prior gives a relative VFE with unknown log normalizer; its prior parameters are fixed.

Source-prior learning is opt-in through `communication.source_rate` and `source_every`. Rate zero preserves the frozen path. `experiments/run_formation.py` runs matching learned and frozen arms with the same synthetic fixture, observations, records, and seeds. Its plots are descriptive mean-field results; they do not establish stochastic formation or a large-population mechanism. The learned arm lowers VFE by construction, since the source step minimizes the categorical KL at fixed Q, so the comparison also plots the fixture-frame field RMSE. `run_multi_seed.py` executes seed and parameter batches sequentially. `run_aggregate.py` reads one batch and saves bootstrap tables and figures; list a grid batch's dotted keys in its `swept_keys`. Differing resolved models cannot be pooled silently; named swept keys must appear in aggregation groups. Aggregation admits only runs with a completed summary and rejects two runs with the same seed and swept values, so a resumed continuation is never counted as an extra seed.

Every run directory contains resolved configuration and environment JSON, preflight storage estimates, geometry/copy/source tables, fixed observations and a diagnostic truth fixture, scalar CSV history, a summary, and authoritative checkpoints. Static PDF/PNG/SVG figures show VFE terms, reference-field error, uncertainty, supports, selected routing, source-row distributions, mean-field coherent blocks, and transport observables. 3D maps use the declared middle z slice. `vfe4.visualization.field_snapshot` exposes the full array for selecting other slices. The fixture is used to generate observations and measure error; inference reads the observations.

To continue the same fixed-data model, call `resume_simulation(Path('.../final_state.pt'), additional_sweeps)` from `vfe4.simulation`. Checkpoints preserve full patch factors, generator recognition, integration and diagnostic RNG streams, source rows, schedule position, and recorder history. They use trusted local Torch serialization. A failed sweep is rolled back: the failed summary names the last accepted sweep and, for a factorization failure, the agents and channel, and `failed_state.pt` holds the last accepted state. No jitter or clipping silently turns a failed model into a successful run. A continuation records `resumed_from` in its summary and reapplies `runtime.deterministic`.

`vfe4.exchange.export_context` saves a chosen context as an explicitly conditioned Gaussian action compatible with MultiAgentELBO's `GaussianAction(J,h,c)`. It records source labels, a generator realization, fixed omitted values, the conditioned recognition law, physical agent/copy identities, maps, priors, source probabilities, and observation normalizers. It does not export a context marginal as an independent spatial model. The payload pickles vfe4 dataclasses, so loading it requires vfe4 and `weights_only=False`; the J, h and c tensors themselves are plain.

Validation evidence and remaining work are in `docs/implementation/progress.md`. `experiments/run_cuda_validation.py` selects the actual CUDA lane and rejects skipped tests. `experiments/run_scaling.py` records configured 512/1024-agent profiles and a five-seed batch, resumes completed profile bookkeeping, and defers when another compute process occupies the GPU. Current measured status is in `docs/performance/scaling.json`; a storage prediction is not a timing or memory measurement.
