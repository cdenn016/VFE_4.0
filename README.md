# VFE 4.0 multi-agent simulation

This suite implements the finite normalized Gaussian realization of the live MultiAgentELBO theory. One engine runs a single context with an agent lattice, local sections over a periodic flat 2D base, or local sections over a periodic flat 3D base. The starting gauge backend is GL(K,R). The design and revised implementation plan are in `docs/superpowers/`.

Open `run_simulation.py` in your editor, select `C:/anaconda/python.exe`, edit `PRESET` and `OVERRIDES`, and press Run. The active entry selects `point_lattice_512`, K=4, CUDA, and 100 sweeps. There are no command-line arguments. The installed interpreter has CUDA Torch; bare Python on this machine has CPU-only Torch. Set `output.viewer=True` for pause, resume, one-sweep, and stop controls. Headless execution uses the same inference engine. A stopped run saves its state and reports `stopped`.

The presets are `tiny_point`, `tiny_spatial_2d`, `tiny_spatial_3d`, `point_lattice_512`, `spatial_2d_512`, `spatial_3d_512`, and `spatial_2d_1024_sparse`. The tiny presets use CPU for formula and continuation checks. Change `population.n_agents` together with its lattice or center-grid dimensions; the loader rejects inconsistent shapes. Full patch Gaussian covariance is the default. `node_blocks` is an explicitly different recognition family; it retains full K by K covariance within each node. The Fisher-natural matter method currently requires `full_patch`. Coverage can be required or explicitly allowed to be incomplete.

The flat connection is induced by the fixed smooth agent frame: `Omega(y,x)=U(y)U(x)^-1`. Inter-agent attending directions each have an independent primitive generator. A formal inverse is not a second likelihood copy. Held links give a normalized fixed Gaussian/source-label model with an exact VFE evaluation. Latent Gaussian links use antithetic samples, analytical matter expectations conditional on those samples, and Gaussian Fisher/BLR updates with the projected true Hessian. Acceptance uses common samples. Independent diagnostic samples report a separate estimate and standard error. Two samples form only one antithetic pair, so an error bar is unavailable. A nonzero loop prior gives a relative VFE with unknown log normalizer; its prior parameters are fixed.

Source-prior learning is opt-in through `communication.source_rate` and `source_every`. Rate zero preserves the frozen path. `experiments/run_formation.py` runs matching learned and frozen arms with the same synthetic fixture, observations, records, and seeds. Its plots are descriptive mean-field results; they do not establish stochastic formation or a large-population mechanism. `run_multi_seed.py` executes seed and parameter batches sequentially. `run_aggregate.py` reads one batch and saves bootstrap tables and figures. Differing resolved models cannot be pooled silently; named swept keys must appear in aggregation groups.

Every run directory contains resolved configuration and environment JSON, preflight storage estimates, geometry/copy/source tables, fixed observations and a diagnostic truth fixture, scalar CSV history, a summary, and authoritative checkpoints. Static PDF/PNG/SVG figures show VFE terms, reference-field error, uncertainty, supports, selected routing, source-row distributions, mean-field coherent blocks, and transport observables. 3D maps use the declared middle z slice. `vfe4.visualization.field_snapshot` exposes the full array for selecting other slices. The fixture is used to generate observations and measure error; inference reads the observations.

To continue the same fixed-data model, call `resume_simulation(Path('.../final_state.pt'), additional_sweeps)` from `vfe4.simulation`. Checkpoints preserve full patch factors, generator recognition, integration and diagnostic RNG streams, source rows, schedule position, and recorder history. They use trusted local Torch serialization. Numerical failures write a failed summary and checkpoint; no jitter or clipping silently turns a failed model into a successful run.

`vfe4.exchange.export_context` saves a chosen context as an explicitly conditioned Gaussian action compatible with MultiAgentELBO's `GaussianAction(J,h,c)`. It records source labels, a generator realization, fixed omitted values, the conditioned recognition law, physical agent/copy identities, maps, priors, source probabilities, and observation normalizers. It does not export a context marginal as an independent spatial model.

Validation evidence and remaining work are in `docs/implementation/progress.md`. `experiments/run_cuda_validation.py` selects the actual CUDA lane and rejects skipped tests. `experiments/run_scaling.py` records configured 512/1024-agent profiles and a five-seed batch, resumes completed profile bookkeeping, and defers when another compute process occupies the GPU. Current measured status is in `docs/performance/scaling.json`; a storage prediction is not a timing or memory measurement. The suite does not change the existing renormalization agent's code or the Research vault.

The October 14 first-release handoff is in `docs/implementation/build-handoff.md`: 51 CPU and 10 explicit CUDA cases passed; all five scale profiles, the five-seed aggregate and ten matched source-control runs completed. Timing, allocator peaks and the preserved uncertain-link failure/repair are in `docs/performance/scaling.md`. Automated Qt viewer controls and offline package imports passed; manual human viewer interaction remains untested.

The numerical dependencies are Torch, NumPy, SciPy, Matplotlib, and pytest for validation. Their package declaration is in `pyproject.toml`. The installed local runtime already provides them. See `docs/model-contract.md` for equations, source labels, coordinate conventions, observable scope, and configuration execution paths.

The Git repository includes source, editable entry points, tests, design/model documentation, JUnit and compact run JSON/CSV evidence. Matched-control comparison figures and the scaling batch aggregate are included. Binary Torch checkpoints, geometry/observation archives, other generated figures, caches and packaging products stay local and ignored. The run records retain the original local paths and environment; the experiment launchers regenerate binary artifacts. The offline wheel can be rebuilt from pyproject.toml, and its local validation record is saved under docs/implementation/.
