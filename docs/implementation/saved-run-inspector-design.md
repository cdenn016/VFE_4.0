# Saved-run inspector, October 16, 2026

The user approved an editable literal CONFIG in run_viewer.py and reserved CUDA execution for their own run. The new launcher selects a checkpoint file or run directory, an explicit display device (CPU by default), and one to four CPU threads. Relative paths resolve beside the launcher; a directory selects its final_state.pt. It opens the existing six-panel dashboard without resuming inference, creates no run directory and writes no checkpoint. Existing active configs are protected.

The continuation loader deliberately restores RNG streams. Add a separate inspection loader using Torch map_location and no RNG restoration. Retain saved dtype, fixed observations, recognition laws, source probabilities and recorder rows. Set only the loaded copy's display-device metadata, including its manifold allocation device; preserve the saved configuration and checkpoint on disk. CPU inspection of a checkpoint with CUDA metadata must not query or initialize CUDA. Loading uses the project's trusted local checkpoint format.

The viewer accepts recorded history directly rather than evaluating VFE or inserting a synthetic endpoint. Empty history is labeled unavailable. Inspection mode disables Pause/resume and One sweep, and Close ends the window. Existing agent, channel, component, context, slice and uncertainty selectors remain available. It displays one stored checkpoint; no intermediate inference states are invented from scalar history. Simulation mode keeps its existing defaults and controls.

Use tiny CPU tests for device mapping, unchanged RNG/state/history, missing paths, empty history and inactive inference controls. Prepare the real Qt test separately and execute it only after focused tests finish, with at most four CPU threads and no process pool/background work. Run one broader CPU pass after final source changes, refresh the package sequentially, preserve prior evidence and update the daily log. No GPU query or numerical CUDA run is part of this implementation.
