# Cue/result memory: live implementation correspondence

This read-only inspection covers the live VFE_3.0 cue/result implementation and its correspondence to the current Research manuscript on October 28, 2026. No model, test, numerical script, GPU query, training run, or benchmark was executed. The only new artifact is this note. Current launcher settings do not identify the settings of a previously successful run.

The implementation realizes a persistent bank of normalized cue/result mechanisms. `CueResultMemoryBlockMLP` registers `nu`, `log_lambda`, `log_pi`, `omega`, `log_result_noise`, and either a dense regression offset or low-rank factors as parameters. These are the learned bank, retained between calls and serialized with the model; the current forward pass does not overwrite them from its input. `forward_moments` computes a posterior and returns its result moments. Its only optional state write is the current component log posterior in the stack-local `regime_state` dictionary. The relevant executable sections are `C:/Users/chris and christine/Desktop/VFE_3.0/vfe3/model/block_mlp.py:2039-2063` and `:2132-2159`. The bank is statistical memory in parameters, not an implemented episodic store of the current token's observations.

At fixed input mean and covariance, the mathematical computation follows the declared cue/result model. In `vfe3/model/cue_result_memory.py:212-230`, the dense path forms `W = C + diag(lambda)`, scores each component with the Gaussian evidence including its log determinant, computes the conditional cue covariance, applies the regression to the cue update, adds result noise, and takes the law of total covariance over component labels. The prior is normalized with `log_softmax` at line 278. The diagonal route, lines 388-477, returns the exact result mean and diagonal of the result covariance for diagonal records; the token's next Gaussian belief retains these moments and loses the full mixture representation. `CueResultMemoryBlockMLP.posterior`, lines 2089-2104 of `block_mlp.py`, selects the dense or diagonal implementation from the covariance layout.

This gives a concrete instance of the local normalized model in `Research/manuscripts/MAgent_Theory_2.0/chapters/01_foundations.tex:170-183`: the presentation can be the component label, its reference law is the learned categorical prior, the evaluator returns a joint cue/result law, and the record kernel measures the cue. The posterior component weights are a belief over these mechanisms; they are distinct from the stored categorical reference prior and from the mechanism parameters. A moment-matched result Gaussian alone is not the complete posterior joint over component, cue, and result. In particular, sharing a bank is sharing a mechanism; it does not imply equal posterior beliefs for different tokens. The manuscript explicitly distinguishes those statements at foundations lines 185-195.

The actual caller first converts the token mean into the reference chart and obtains its reference covariance. It can then apply block normalization before calling the memory. `vfe3/model/block.py:429-461` performs those operations, `:475-485` replaces the mean and covariance with the returned moments, and `:491` returns them to the local chart. There is no additional additive residual around this cue/result call. Its identity-like initialization instead sets the result center equal to the cue center and the regression equal to the identity; it still performs same-state Bayesian conditioning and adds positive result noise. The exact same-state mean reduction and the additional covariance term are stated in `Research/manuscripts/Attention/cue_result_memory.tex:179-188`. These facts do not claim that all other sublayers lack residual paths.

Parameter tying and posterior carry are separate implementation choices. `vfe3/model/model.py:451-457` either stores one shared module at every layer index or creates separate banks. With tying, labels retain a common bank meaning across depth. Optional regime carry creates a fresh dictionary inside the stack call, writes the present layer's posterior log weights, and promotes them to `previous` for the next layer (`vfe3/model/stack.py:122-163`; `block_mlp.py:2151-2158`). The carried prior is computed from the previous weights and a sticky or learned stochastic transition, multiplied by the static prior and tempered by `regime_beta` (`block_mlp.py:2072-2082`). This dictionary is per stack invocation; these lines do not implement persistent regime inference across successive forward calls. Validation requires tied banks for non-off carry (`vfe3/config.py:2233-2238`).

The launcher currently sets `use_block_mlp=True`, `block_mlp_tie_layers=True`, `block_mlp_mode="cue_result_memory"`, posterior covariance, exact inference, rank-2 regression, and `block_memory_regime_transition="off"` (`train_vfe3.py:200-221`). It uses `gaussian_frame_diagonal` at line 160, reference coordinates at line 181, and block LayerNorm with covariance passthrough at lines 237-238. Both `fully_gauge_covariant` and `principled_exact_route` overrides are false at lines 105 and 116. Consequently, this current configuration shares learned mechanisms across layers but does not carry posterior component weights through depth. Its LayerNorm means the observation supplied to the local Bayesian block is the normalized reference mean with the configured covariance treatment. The separate principled-route override can select different normalization and carry behavior; it is not active in this launcher snapshot. No historical run artifact was inspected here, so none of these settings explains or validates a reported successful run.

Learning of the bank is outer task training. `vfe3/train.py:337-354` puts the bank parameters into optimizer groups, deduplicating a tied module and exempting its log variances, log weights, and transition logits from weight decay. The ordinary training step backpropagates the model loss at lines 925-933 and steps the optimizer at line 1289. The cue/result block explicitly rejects an EM term (`block_mlp.py:2145-2147`), and configuration validation requires its weight to be zero (`vfe3/config.py:2255-2257`). Thus exact local conditioning does not imply an implemented local sufficient-statistic learner, online EM update, or learning rule without backpropagation. The current manuscript states this boundary at `cue_result_memory.tex:369-371` and `:411-414`.

The response identity also has a specific boundary. `cue_result_memory.tex:193-226` fixes a positive-definite record covariance and every component parameter before asserting

\[
D_{\xi}\mathbb E[Y\mid O=\xi]
=\operatorname{Cov}(Y,X\mid O=\xi)C^{-1}.
\]

For same-state retrieval the whitened Jacobian is positive definite; a free result regression removes that restriction. This is a partial derivative of the local memory map at fixed covariance and prior. It is not the total derivative of the full stack, where the covariance, upstream attention, normalization, and optional carried prior can depend on the input. The declared Gaussian observation is a modeling event, not an established independent observation produced by the upstream network (`cue_result_memory.tex:147-149`). The manuscript likewise does not establish one joint law of the stack or monotone free-energy descent through depth (`:411-414`).
